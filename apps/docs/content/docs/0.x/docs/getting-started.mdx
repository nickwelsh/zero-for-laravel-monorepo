---
title: Getting started
description: Install v0.9 and generate controller-first queries and mutations.
---

Install matching **v0.9.0** Composer and npm packages and deploy their generated output together.
The optional `@nickwelsh/zero-table` package also uses **0.9.0**.

- PHP 8.3+, Laravel 12/13, PDO PostgreSQL, and PostgreSQL 15+ with logical replication.
- Native Zero client and cache **1.11.3**, pinned together.
- React 18/19, Inertia Laravel 3, and `@inertiajs/react` ^3.8.0 for automatic live page props.
- Node 22.18+ on the 22.x line or 24.11+, and a TypeScript 7-compatible toolchain.

In an existing Laravel application:

```sh
composer require nickwelsh/zero-for-laravel:^0.9.0
pnpm add @nickwelsh/zero-for-laravel@^0.9.0 @rocicorp/zero@1.11.3
```

For Inertia pages, install `inertiajs/inertia-laravel:^3.0` and
`@inertiajs/react@^3.8.0` if they are not already present. Native Zero queries and
mutations do not require the Inertia adapter. Wayfinder is optional; its
`dev-next` integration is not a dependency of the production Composer package.

The [shared todos example](https://github.com/nickwelsh/zero-for-laravel-monorepo/tree/main/examples/todos)
contains installation commands, migrations, authentication, sharing, and the local
Composer/pnpm wiring. Its application requires PHP 8.4.1+.

Configure Laravel's PostgreSQL connection and migrate the application's tables.
Define the application's string-backed `App\Enums\ZeroContext` enum and attributed
resolver, then set both `context` and `context_resolver` in `config/zero.php`.
Follow the [typed context setup](./configuration.mdx#typed-context-and-resolver);
generation reflects signatures rather than executing resolver methods.

Opt models in with `HasZeroQueries`; their Composer namespaces are discovered automatically.
Define column allowlists and supported Eloquent relationships. Protect private
models with ordinary Laravel policies, `HasPolicyVisibility`, and explicit
`visibleTo($request->user())` on each protected query path. Public models must be
marked deliberately with `#[ZeroForLaravel\Attributes\ZeroPublic]`. See
[policy bindings and managed grants](./authorization.mdx#configure-bindings-and-managed-grants)
for RBAC/ABAC setup and transactional sharing. Zero global scopes remain useful
for business constraints and creation defaults; they do not replace visibility.

Publish permissions configuration and migrations, configure the subject/resource
bindings, migrate, and backfill any existing ACLs into managed grants. Rebuild the
private projections before generation. Declare queries and mutations on registered
controller routes, then generate against that database:

```sh
php artisan vendor:publish --tag=zero-config
php artisan vendor:publish --tag=permissions-config
php artisan vendor:publish --tag=permissions-migrations
php artisan migrate
php artisan permissions:rebuild
php artisan zero:generate --react
php artisan zero:sync-publication --dry-run
```

Review the publication before applying it. Never expose the private cache API key
to the browser. Authenticate end users independently of the cache.

Apply the reviewed publication with `php artisan zero:sync-publication`, configure
the [cache and authentication boundary](./replication.mdx#configure-zero-cache),
and set the public cache URL in the generated editable `zero.config.ts`.
For local startup and diagnostics, see [local development](./local-development.mdx).

Define [models and scopes](./models.mdx), declare [controller queries](./queries.mdx),
and register [controller mutations](./mutations.mdx). Install the
[Inertia adapter](./react.mdx) in the page resolver and pass both `userID` and typed
`context` to the provider. Keep policies, Gates, and FormRequest association checks;
creation defaults do not authorize writes. Deploy generated PHP and TypeScript
together, and use `zero:generate --check` to detect stale output. Existing 0.x
applications should follow the [breaking migration mappings](./constraints.mdx#migrating-existing-0x-applications).
