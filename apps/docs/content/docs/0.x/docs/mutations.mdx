---
title: Controller mutations
description: Compile typed controller actions into native optimistic and authoritative execution.
---

Explicitly annotate an action on a registered Laravel route:

```php
use ZeroForLaravel\Attributes\ZeroMutation;

/** @return array{id: string} */
#[ZeroMutation]
public function store(StoreTaskRequest $request): array
{
    $task = Task::create($request->validated());

    return ['id' => $task->id];
}
```

The FormRequest retains preparation, authorization, rules, and validation hooks.
Annotated actions are native-only: ordinary HTTP requests to their route return
405 instead of bypassing stable preparation or invoking a second write path.
Real route middleware and binding run at the authoritative boundary. Call Gates
and policies explicitly in the action or its request; an attribute is not a grant
of permission. Reload and lock state-dependent bound records with
`$mutation->reloadForUpdate($task)` before reauthorization and writes.

One checked operation tree generates native client execution and authoritative
Eloquent execution. Prepared IDs and timestamps are reused across replay and
delivery. Metadata stays separate from mass-assignable input. Unsupported shared
PHP fails generation rather than silently disappearing.

## Optimism strategies

- `#[ZeroMutation]`: generated prediction from supported PHP.
- `#[ZeroMutation(optimism: 'custom')]`: an explicitly supplied native projection.
- `#[ZeroMutation(optimism: 'disabled')]`: enqueue without speculative writes.

All three use the same native protocol, validation, results, and lifecycle. Pass
custom projections to the generated `createControllerMutationBindings` factory.
When a custom action exists, the React module exports `createZeroBindings(projections)`
instead of constructing a provider without the required projections. Call it once
in an application-owned module and export its `ZeroProvider` and `actions`.
Key each projection by the imported action's literal `action` property, for example
`createZeroBindings({ [notify.action]: async ({ tx, args }) => ... })`, rather than
typing a PHP controller path by hand.
Declare their client result independently when it differs from the server result.
Missing required bound rows produce the declared pre-write no-op prediction;
the valid intent still reaches Laravel.

## Client invocation

```tsx
import { useControllerMutation } from '@nickwelsh/zero-for-laravel/react';
import { store as create } from '@/zero/App/Http/Controllers/TaskController';

const createTask = useControllerMutation(create);
const saved = await createTask({ title: 'A task' });
console.log(saved.id);
```

Exports follow the PHP namespace and method name. Each controller module also
exports named input and result types, such as `StoreInput` and `StoreResult`.
The same imports work with custom optimism: the hook uses the bindings installed
by the current generated `ZeroProvider`, including its custom projections.

## Prepared fields

Generated creates prepare identities and time **before** calling `zero.mutate`.
`HasUuids` selects UUID generation; `HasUlids` selects ULID generation. Eloquent's
timestamp settings determine the created/updated columns, including renamed
`CREATED_AT` and `UPDATED_AT` columns. Auto-incrementing keys are not supported
for generated creation. These values stay outside FormRequest business input:
forms send fields such as `title`, not required IDs or timestamps.

Preparation runs once per submission. The frozen native arguments carry the same
values through optimistic execution, replay, and authoritative PHP execution.
Updates preserve creation time and use the prepared time for the updated column.
Server authorization and format validation still apply; client time is not a
trusted audit clock. Arbitrary server-only Eloquent creates in custom/disabled
actions are not automatically transformed into client-prepared creates.

Override generators globally when constructing the generated provider:

```ts
import { v7 as uuid } from 'uuid';
import { createZeroBindings } from '@/zero/generated.react';

export const { ZeroProvider } = createZeroBindings({ uuid, now: () => new Date() });
// With custom optimism: createZeroBindings(projections, { uuid, now: () => new Date() }).
```

Or pass overrides as the hook's third argument:
`useControllerMutation(create, {}, { uuid, now: () => new Date() })`.
The supported generators are `uuid`, `ulid`, and `now`. Overrides must return valid,
distinct identities and a valid nonnegative date. Never generate values inside an
optimistic projection: Zero can replay it more than once.

Supply route arguments for bound actions. For direct native control, prepare once
with a binding from `createControllerMutationBindings`, using
`binding.prepare(input, routeArguments, preparation)`, then call `zero.mutate(request)`.
`.client` means local application; `.server` means authoritative outcome. Parse
result data with the generated client/server result schemas. `void`, explicit
null, and structured JSON remain distinct. Model and HTTP-response serialization
are not implicit result contracts.

The hook tracks pending state, field errors, local application, server acceptance,
and committed-but-undecodable results separately. Navigate and show authoritative
success only after server acceptance. Unmounting stops observation, not the queued
write. Unmodified Inertia forms do not automatically submit through Zero.

Business changes, native progress, and returned data commit atomically. Application
rejections roll back business writes and persist an error outcome. Duplicate
delivery does not rerun the action; a lost callback response can recover through
native persisted results. These are not durable JavaScript promises across reloads.

Use `conceal: true` for actions that must normalize private-resource errors. Keep
external effects server-only and use a transactional outbox plus idempotent workers
when delivery must survive process failure. See [shared operations](./domain-mutations.mdx).
