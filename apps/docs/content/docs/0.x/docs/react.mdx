title: React and Inertia
description: Inject controller-declared live props into plain React page components.
---

Run `php artisan zero:generate --react`. It writes the bound provider and creates
an application-owned `zero.config.ts` once. Set the public cache URL there; never
put the cache API key in browser configuration.

Install the query bindings in Inertia's page resolver:

```tsx
import { createInertiaAdapter } from '@nickwelsh/zero-for-laravel/inertia';
import { bindings } from '@/zero/generated.queries';

const livePages = createInertiaAdapter(bindings);
// After loading the requested component in createInertiaApp.resolve:
return livePages.wrap(module.default, page);
```

Put the generated `ZeroProvider` in the authenticated persistent layout, outside
the wrapped page. Supply both native `userID` and the generated typed `context`
used for local queries and creation defaults. With the two-case enum from
[configuration](./configuration.mdx#typed-context-and-resolver), for example:

```tsx
<ZeroProvider userID={identity} context={{ user_id: user.id, tenant_id: authorizedTenantId }}>
    {children}
</ZeroProvider>
```

Here `identity` is the application's native Zero identity string; it is not
implicitly read from `context.user_id`, and `userID` does not populate that key.
The generated context type follows all configured resolver return types (including
nullable fields). Supply the matching values; a custom enum need not have a
`user_id` case at all. Laravel independently resolves trusted `ResolvedContext`;
browser context is not authority. Identity or tenant changes isolate subscriptions
and local storage; native Zero owns construction and cleanup.

```tsx
import type { QueryData } from '@nickwelsh/zero-for-laravel/react';
import type { index } from '@/zero/App/Http/Controllers/TaskController';

export default function Tasks({ tasks }: { tasks: QueryData<typeof index.tasks> }) {
    if (tasks.status === 'loading') return <p role="status">Loading tasks…</p>;
    if (tasks.status === 'failure') return <p role="alert">Unable to load tasks.</p>;
    return tasks.data.map((task) => <p key={task.id}>{task.title}</p>);
}
```

Zero does not generate a global page namespace. Define page props in your application
and infer live data from the exported queries. Ordinary props remain application-owned.

## Optional Wayfinder page types

If you use `laravel/wayfinder` **`dev-next`** to generate `Inertia.Pages`, register
`ZeroForLaravel\WayfinderServiceProvider::class` in `bootstrap/providers.php`.
This is opt-in and requires Wayfinder's next-branch Inertia converter; the stable
route-only Wayfinder release does not expose it. Zero does not install Wayfinder
as a production dependency.

Generate Zero's contracts first, then let Wayfinder generate its own declarations:

```sh
php artisan zero:generate --react
php artisan wayfinder:generate --fresh
```

The integration customizes Wayfinder's converter before it writes the page type.
It changes only props in Zero's generated query registrations for that controller
method and component. Wayfinder still owns the page name, shared data, ordinary
props, and output file. There is no second declaration or global type override.
For example, its dashboard prop becomes:

```typescript
lists: import('@nickwelsh/zero-for-laravel/react').QueryData<
    (typeof import('@/zero/App/Http/Controllers/DashboardController'))['index']['lists']
>;
```

This references the generated query instead of serializing the PHP `Query` class.
It preserves related rows, decoded `Date` fields, and singular-result `undefined`,
and includes the live prop's loading, error, and pagination API. It describes props
**after the Inertia live adapter has injected them**, not raw server page JSON.
Continue to install `createInertiaAdapter` in the resolver.

`zero.wayfinder.module` defaults to `@/zero`. Set it to the TypeScript module root
containing your generated controller modules if you use another alias or directory.
Relative module roots resolve from Wayfinder's generated `types.d.ts`, not from
your PHP configuration file. Regenerate Zero whenever declarations change, and use
`zero:generate --check` in CI to catch stale registrations. This integration uses
the current `dev-next` converter API; an upstream breaking change may require an update.

## Editable live inputs

The page adapter adds `inputs` to each injected live prop. Its `values` are the
controller FormRequest's validated fields, not route bindings or trusted context:

```tsx
import type { QueryData } from '@nickwelsh/zero-for-laravel/react';
import type { index } from '@/zero/App/Http/Controllers/DashboardController';

export default function Dashboard({ lists }: { lists: QueryData<typeof index.lists> }) {
    return (
        <select
            value={lists.inputs.values.status ?? 'all'}
            onChange={(event) => {
                const status = lists.inputs.options.status.find((value) => value === event.target.value);
                if (status !== undefined) lists.inputs.set({ status });
            }}
        >
            {lists.inputs.options.status.map((status) => (
                <option key={status}>{status}</option>
            ))}
        </select>
    );
}
```

This example assumes the status rule shown in [query inputs](./queries.mdx#formrequest-inputs).
`set(partial)` shallow-merges; `set(current => partial)` uses the latest values.
Undefined removes an optional field; null requires a nullable rule. Invalid patches
throw before changing the subscription. Input changes reset pagination, and
`reset()` restores the page's initial inputs. Partial visits omitting a live
binding preserve local inputs; a replacement binding supplies new inputs.
Queries without a FormRequest have empty inputs and reject nonempty patches.
Date inputs use canonical JSON strings.

Resubscription does not make an Inertia request or change the URL by default.
To preserve chosen scalar filters in client-side history, opt in per component,
prop, and field (component names match `Inertia::render`):

```ts
const livePages = createInertiaAdapter(bindings, {
    url: { dashboard: { lists: { status: 'status' } } },
    history: 'replace', // Use 'push' for back/forward filter navigation.
});
```

Only mapped fields enter the URL: undefined removes the parameter, null becomes
an empty value, and booleans use `1`/`0`. Nested objects/lists cannot be mapped.
Inertia history stores serializable bindings, never live rows. Reloads go through
Laravel's FormRequest again; normalize numeric and boolean URL strings there.
`InferLiveQueryInputs` and `InferLiveQueryOptions` infer individual contracts.
`QueryData` includes both decoded rows and editable inputs; `Data` alone describes
the read-only `useData` result. Native calls still pass their inputs explicitly.

## Headless tables and ordered grouping

`@nickwelsh/zero-table` uses generated PHP table capabilities for authorized live
rows and snapshot group directories/counts. Declare allowed dimensions and ordered
default rules in your table's `definition(TableContext $context): Table`:

```php
return Table::for(Todo::class)->visibleTo($context->user())
    ->allowedGroups([
        AllowedGroup::field('completed'),
        AllowedGroup::belongsTo('list')->label('name'),
    ])
    ->defaultGroupBy([
        ['field' => 'completed', 'direction' => 'desc'],
        ['field' => 'list', 'direction' => 'asc'],
    ])->maxGroupDepth(2);
```

`Table`, `TableContext` and `AllowedGroup` are in `ZeroForLaravel\Tables`. Generate
the descriptor with `php artisan zero:generate`, then consume it inside the
existing Zero provider/access boundary:

```tsx
import { column } from '@nickwelsh/zero-table';
import { DataTable, useDataTable } from '@nickwelsh/zero-table/inertia';
import todos from '@/zero/tables/todos';

const columns = [column.text('title')];

function Todos() {
    'use no memo';
    const table = useDataTable(todos, { columns, urlState: true });
    // Render your own rows/headers in a viewport under one DataTable.Root.
    // The descriptor's defaults are equivalent to:
    // groupBy: [{ field: 'completed', direction: 'desc' }, { field: 'list', direction: 'asc' }]
    return <DataTable.Root table={table}>{/* Application-owned UI */}</DataTable.Root>;
}
```

Rule order defines nesting. Each level orders its keys in its own direction with
**NULLS LAST in both directions**. Relation groups order foreign-key values, not
labels. Row `sort` remains independent; changing group direction does not reverse
rows within a leaf. Allowlists, maximum depth, authorization, mandatory scopes,
nested filters and multi-sort retain their existing semantics. Presentation and
grouping controls remain application-owned.

Directory pagination uses opaque keyset cursors scoped to the full grouping rules,
including order/direction, plus contract, actor/context, filter and directory path.
Changing rules clears metadata, cancels old requests and ignores stale responses.
Directories/counts are snapshots; changes between pages can require a refresh.
Live row windows grow prefixes; snapshot counts never establish row exhaustion.

`setGroupBy` clears expanded IDs on an actual field/order/direction change, while
identical rules preserve them. Full controlled state or URL restoration can
explicitly supply both rules and expansion. Collapsing a parent still preserves
descendant expansion when rules have not changed.

### Version-2 migration and URL parity

Replace all legacy string-array grouping in PHP defaults, TypeScript state and
saved views with explicit `{ field, direction }` rules. Capabilities, metadata
requests/responses and table URL envelopes now use **version 2**. Regenerate
descriptors and deploy matching PHP/TypeScript output together; contract
fingerprints include the protocol version. Version-1 URLs and invalid version-2
string-array grouping fall back to the whole namespace's application/descriptor
defaults, with no silent conversion. Invalid defaults and programmatic writes throw.

The browser `/react` and `/inertia` hooks use the same version-2 URL contract as PHP
`TableURLState`, including rule directions, expansion, validation and fallback.
Inertia's hook restores from `usePage().url` during SSR, uses client-side router
writes, merges pending changes across tables, and restores Back/Forward without
losing unrelated parameters or scroll. For PHP-first multi-source pages, use
`TableURLState` with a controlled `createPageURLState` coordinator rather than a
second `urlState` owner. See the repository's `docs/URL_STATE.md` and
`examples/todos/resources/js/pages/url-state.tsx` for that integration, and
`packages/table/README.md` for rendering and editing examples.

## Native Zero access

The generated hook returns the actual, schema-typed Zero instance. Query factories
produce native requests, usable by `run`, `preload`, `materialize`, or Zero's `useQuery`:

```tsx
import { useQuery } from '@rocicorp/zero/react';
import { useZero, actions } from '@/zero/generated.react';
import { index } from '@/zero/App/Http/Controllers/TaskController';
import { store } from '@/zero/App/Http/Controllers/TaskController';
import type {
    InferQueryInput,
    InferQueryResult,
    InferMutationInput,
    InferMutationResult,
} from '@nickwelsh/zero-for-laravel';

const zero = useZero(); // Inside a component under ZeroProvider.
const [tasks] = useQuery(index.tasks({}));
const rows = await zero.run(index.tasks({}));
const submission = zero.mutate(actions[store.action].prepare({ title: 'New task' }));
await submission.client;
const outcome = await submission.server;

type QueryInput = InferQueryInput<typeof index.tasks>;
type QueryResult = InferQueryResult<typeof index.tasks>;
type CreateInput = InferMutationInput<typeof store>;
type CreateResult = InferMutationResult<typeof store>;
```

Supply the inputs required by your controller. Native queries preserve wire-format
values, including numeric timestamps. `index.tasks.live(input)` instead returns the
selection accepted by `useData`, whose dates are decoded to `Date`. Its row type is
`InferLiveQueryResult<typeof index.tasks>`. Neither path requires an Inertia page.

Mutation requests must come from the bindings registered with that Zero instance.
The generated provider exports its `actions` and native `mutators`; applications
with custom projections obtain both from their `createZeroBindings(projections)`
result. Outside React, use `createControllerMutationBindings` from `.mutations.ts`
and pass its `mutators` to `new Zero`. No React lifecycle or global singleton is
required by that factory. `useZero` follows native lifecycle semantics and must run
under the initialized provider, not the pre-initialization Inertia shell.

`InferMutationResult` describes the decoded authoritative result. Native `.server`
returns a success/error envelope; on success, parse its `data` with the action's
`serverResultSchema`, or use the binding's `execute` helper. Optimistic `.client`
results can differ from authoritative results.

No per-prop `useQuery` is necessary. Rows and related rows are plain decoded data,
without a `.data` wrapper or mutation methods. Live objects distinguish loading,
refreshing, success, stale data, failure, and idle/disabled state. Connection status
does not imply query completeness.

Infinite props expose `loadMore`, `hasMore`, and loading state; cursor-page props
expose navigation. Completion determines whether more data is known to exist.
Partial reloads and history use reserved page metadata; query descriptors never
replace the omitted live prop in serialized page props. Initial SSR and hydration
render a deterministic loading shell before native client initialization.

Use [controller mutation bindings](./mutations.mdx) for forms. Pages do not receive
model objects with bound write methods. See the shared todos example for the full
resolver, layout, connection options, forms, and sharing workflow.
