---
title: Upgrading to v0.5
description: Migrate from model-centric v0.4 contracts to controller-first queries and native mutations.
---

**v0.5.0 is a breaking minor release.** Upgrade Composer and npm together, pin both
Zero client and cache to **1.11.3**, and regenerate the entire contract set. Existing
v0.4 generated code and queued mutations are not a compatible deployment format.

## Replace model-centric application code

| v0.4 application pattern                               | v0.5 application pattern                                                           |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| Browser model selections and model query methods       | Controller `Model::zeroQuery()` props and named native query factories             |
| Snapshot wrappers, `toPlain()`, and bound CRUD methods | Plain decoded rows and explicit generated controller actions                       |
| `DomainMutation` registrations and `actions.name`      | Routed `#[ZeroMutation]` controller methods and named action imports               |
| Separate operation-result HTTP reads                   | Native Zero client/server outcomes persisted with mutation progress                |
| Handwritten per-prop subscription hooks                | Inertia resolver adapter and generated query bindings, or explicit native requests |

Model definitions still own columns, casts, relationship registration, visibility,
and context fills. Keep read authorization and write policies separate. Existing
low-level compatibility symbols in the reference do not make old generated
application contracts compatible with v0.5.

## Install and migrate

1. Stop issuing old application writes and decide how to settle any offline queued
   operations before replacing their registrations. There is no automatic replay
   migration or retention of old action identities.
2. Install `nickwelsh/zero-for-laravel:^0.5.0` and
   `@nickwelsh/zero-for-laravel@^0.5.0`. Upgrade `@rocicorp/zero` and zero-cache
   together to `1.11.3`. Automatic live pages require Inertia Laravel 3 and
   `@inertiajs/react` ^3.8.0; the workspace uses TypeScript 7.
3. Add `HasZeroQueries` to participating models. Move query declarations into
   registered controller responses and filters into FormRequests. Annotate write
   actions with `#[ZeroMutation]`; keep FormRequest authorization and explicit
   policy checks. These actions return void or explicit JSON, not redirects.
4. Choose generated, custom, or disabled optimism explicitly. Move external effects
   into server-only boundaries; use a transactional outbox for durable delivery.
5. Replace snapshot/CRUD callers with plain row access and generated action imports.
   Await the authoritative result before reporting success. A result decoding error
   after commit must not cause automatic resubmission.

Review the new `controller_output`, `mutation_output`, and optional
`wayfinder_import` configuration keys rather than overwriting local configuration.
`domain_mutations` is a legacy registration setting, not the new application API.

## Regenerate and deploy matching artifacts

Against the migrated application database:

```sh
php artisan zero:generate --react
php artisan zero:sync-publication --dry-run
php artisan zero:generate --check
```

Generation writes `generated.ts`, `.queries.ts`, `.mutations.ts`, optional
`.react.ts`, the controller modules and owned-file manifest, and
`bootstrap/zero-{queries,mutations}.php`. Keep all of them together in deployment.
Exclude them from formatters. Preserve application-owned `zero.config.ts` and set
its public cache URL; never put the private cache key there.

Install `createInertiaAdapter(bindings)` in the resolver and put the generated
provider in the authenticated persistent layout. Use `QueryData<typeof index.prop>`
for injected props, `InferLiveQueryResult` for decoded rows, and `InferQueryResult`
for native wire rows. Zero emits no global page namespace. If using Wayfinder
`dev-next`, opt into its provider integration and generate Wayfinder after Zero.

Review and apply the dedicated publication, deploy PHP registrations and browser
contracts together, then start the matching cache. Verify an authenticated live
subscription, an upstream update, authoritative mutation acceptance/rejection,
and user isolation before resuming normal traffic. Keep callback authentication,
cookie forwarding, and CSRF exceptions scoped to the two cache callbacks.

No package-owned application data migration is required. Application schema changes
remain application-owned. Do not delete a shared database, mutation progress, or
replica as a generic upgrade step; coordinate any cache-format recovery with Zero's
deployment guidance. See [replication](./replication.mdx),
[mutations](./mutations.mdx), and [React](./react.mdx) for the complete contracts.
