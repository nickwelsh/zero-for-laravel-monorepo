Models own replication metadata and row visibility. Controllers own queries and
mutation actions. The generated client exposes plain row types, not model instances
with `query`, `update`, or `destroy` methods.

```php
use Illuminate\Database\Eloquent\Concerns\HasUuids;
use Illuminate\Database\Eloquent\Model;
use ZeroForLaravel\Concerns\HasZeroQueries;
use ZeroForLaravel\ContextField;
use ZeroForLaravel\Definition\ZeroDefinition;

class Task extends Model
{
    use HasUuids, HasZeroQueries;

    protected $fillable = ['title', 'done'];
    protected $visible = ['id', 'user_id', 'title', 'done', 'created_at', 'updated_at'];

    protected function casts(): array
    {
        return ['done' => 'boolean'];
    }

    public static function zero(): ZeroDefinition
    {
        return ZeroDefinition::make()
            ->authorize('user_id', '=', ContextField::UserId)
            ->fillFromContext('user_id', ContextField::UserId);
    }
}
```

Register every participating relationship target. Use `relations(...)` to expose
schema relationships, `authorizeRelation(...)` for mandatory related visibility,
and `publicReads()` only for deliberately public rows. Missing required context
denies access. Read visibility never grants write permission.

## Columns and privacy

The same resolved column plan drives generated TypeScript and the dedicated
PostgreSQL publication. Nonempty `$visible` is the default allowlist.
`ZeroColumns` replaces it; `$hidden` and `ZeroExclude` subtract columns.
`ZeroIncludeColumns` deliberately opts columns back in but cannot expand an
explicit `ZeroColumns` allowlist. Accessors and appended properties are not stored
columns and do not become replicated values.

Primary keys, enabled timestamps, authorization/context fields, and relationship
keys must remain available. Missing required columns fail generation instead of
silently expanding exposure. `$fillable` separately controls write fields; it does
not hide replicated data. Ownership, primary keys, and lifecycle timestamps are
not patchable business input.

UUID/ULID identities support generated optimistic creation. Numeric identities
can use explicitly disabled optimism for authoritative creation. See
[records and casts](./records-and-casts.mdx) and [authorization](./authorization.mdx).
