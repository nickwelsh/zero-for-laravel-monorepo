---
title: Related writes
description: Create related records in one checked controller mutation.
---

Write related operations in the controller or a checked shared helper. The old
`Model.create().with(...)` browser API is replaced by controller action bindings.

```php
#[ZeroMutation]
public function store(StorePersonRequest $request): void
{
    $data = $request->validated();
    $person = Person::create(['name' => $data['name']]);
    if (isset($data['email']) && $data['email'] !== '') {
        Email::create(['person_id' => $person->id, 'email' => $data['email']]);
    }
}
```

Register both models and authorize the relationship in Laravel. The compiler
allocates stable creation-site identities, so the child uses the same parent ID
locally and authoritatively. A rejected child write rolls back the parent too.
The caller does not submit a table-write graph or choose arbitrary model methods.

Explicit operations use `Mutation::create(Model::class, data: ..., key: ...)`.
Supported bounded list loops require unique stable item keys; preparation derives
UUID identities by item key rather than traversal position. Ambiguous identity
allocation and unsupported loops fail generation. Repeated ULID creation is not
part of this initial subset.

All writes must use the configured transaction connection. Cross-database writes
and external services are not made atomic by nesting them in a PHP callback.
