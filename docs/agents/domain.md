# Domain docs

This repository uses a single context. The glossary lives at `GLOSSARY.md` and architecture decision records live in `docs/adr/`.

Before exploring the codebase, read the root glossary and any ADRs relevant to the work when those files exist. Proceed silently when those paths are absent. The `domain-modeling` skill creates them as terms and decisions are settled.

Use glossary terms in issue titles, proposals, hypotheses, and test names. If a concept needs a term the glossary lacks, check the project's existing language and surface genuine gaps through `domain-modeling`.

When a proposal conflicts with an ADR, identify the ADR and explain why the decision should be reopened.
